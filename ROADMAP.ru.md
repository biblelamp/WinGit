# Дорожная карта WinGit

*English version: [ROADMAP.md](ROADMAP.md)*

Дорожная карта сравнивает WinGit с возможностями известных коммерческих
Git-клиентов и упорядочивает работу по приоритетам. Сначала — безопасность и
понятность для новичков в Git, затем — функции для опытных пользователей.

## Текущее состояние

- Репозитории: открытие, создание, клонирование, удаление из списка.
- Панели: файлы, ветки, история с графом коммитов, diff.
- Рабочая копия: stage / unstage / discard целыми файлами, коммит.
- Окно коммита: незаконченное сообщение сохраняется как черновик репозитория и
  подставляется снова (после коммита очищается); показан пользователь Git (имя и почта).
- Diff: переход к следующему / предыдущему изменению (F7 / Shift+F7), новый файл
  открывается на первом изменении; двойной щелчок по файлу открывает его diff в отдельном
  развёрнутом окне; поиск в diff (Ctrl+F, F3 / Shift+F3); внутри строки
  подсвечиваются изменённые слова, полоса сбоку показывает все изменения файла.
- История: локальная ветка и её удалённая ветка на одном коммите показаны одним
  ярлыком; длинные имена веток сокращаются.
- Удалённые репозитории: fetch (вручную и в фоне), pull, push, запрос логина.
- Ветки: создание, переименование, удаление, переключение; merge и его отмена.
- Теги: создание, переименование, удаление, push.
- Stash: спрятать (по желанию вместе с новыми файлами), применить, применить и удалить, удалить.
- Отслеживание изменений на диске с автообновлением.
- Окно настроек: язык, тема, интервал автоматического fetch (или выключен);
  пользователь Git показан только для чтения.
- Интерфейс на английском, русском и чешском.

Известные пробелы:

- История показывает только последние 50 коммитов.
- Нет инструментов разрешения конфликтов, хотя merge и pull могут их создать.

## Этап 0 — до первой бета-сборки

Всё, без чего новичок застрянет или потеряет работу.

1. **Полная история** — подгрузка коммитов порциями при прокрутке, без лимита
   в 50, с виртуализацией.
2. **Конфликты** — список конфликтных файлов; «взять мою версию» / «взять их
   версию» / «отметить как решённый»; открытие во внешнем редакторе; понятный
   баннер «идёт слияние: решите конфликты или отмените».
3. ~~**Stash** — спрятать, применить, применить и удалить, удалить.~~ Готово.
4. ~~**Amend** — исправить последний коммит (сообщение и файлы); предупреждать,
   если он уже отправлен.~~ Готово: только для ещё не запушенного коммита (иначе
   флажок недоступен и подсказка объясняет почему).
5. **Понятные ошибки** — перевод сырого stderr git на человеческий язык
   (например, «удалённая ветка ушла вперёд, сначала сделайте pull»).
6. **Настройки** — ~~тема~~, ~~интервал авто-fetch~~ готово; имя и email
   пользователя показаны (в настройках и в окне коммита), но пока не редактируются;
   осталось: путь к git, изменение пользователя и проверка перед первым коммитом.

## Этап 1 — ближайшие версии: основной набор функций

1. **Частичный стейджинг** — фрагменты и отдельные строки через
   `git apply --cached`.
2. **Действия над коммитом в истории** — файлы и diff коммита, checkout,
   revert, cherry-pick, reset (soft / mixed / hard) с явными предупреждениями.
3. **Поиск и фильтр в истории** — по сообщению, автору, хешу, пути.
4. **История файла и blame.**
5. **Сравнение** — двух коммитов, двух веток, ветки с рабочей копией.
6. **Remote** — добавить / изменить / удалить; push с выбором ветки и upstream;
   `--force-with-lease` с подтверждением.
7. **Удобства** — добавить в `.gitignore` из контекстного меню, открыть в
   проводнике / терминале, копировать хеш, внешний diff/merge-инструмент.

## Этап 2 — средняя перспектива

1. **Rebase** — обычный и интерактивный (переставить, объединить,
   переименовать коммиты), с продолжением и отменой.
2. **Встроенный трёхсторонний редактор конфликтов.**
3. **Reflog** в виде функции «вернуть потерянное».
4. Submodules, Git LFS, worktrees.
5. Подпись коммитов (GPG / SSH), показ вывода хуков.
6. Группы репозиториев, несколько открытых репозиториев (вкладки), горячие
   клавиши.
7. ~~Локализация (русский, чешский)~~ готово; автообновление.
8. Сборки для macOS (DMG) в CI (сборки для Linux DEB/RPM уже есть).

## Этап 3 — дальняя перспектива

1. **Интеграция с хостингами** — GitHub, GitLab, Bitbucket: pull requests,
   комментарии ревью, проверки, ссылки на issues.
2. **Поддержка рабочих процессов** — ветки feature / release / hotfix в стиле
   git-flow.
3. **Большие репозитории** — 100k+ коммитов, сотни тысяч файлов, частичный
   клон.
4. Отдельное окно истории (весь репозиторий или один файл), сравнение каталогов.
5. Расширяемость — пользовательские команды, возможно, API плагинов.
